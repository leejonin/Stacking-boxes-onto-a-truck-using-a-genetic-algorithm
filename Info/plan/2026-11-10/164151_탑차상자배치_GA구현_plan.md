## 1. 목적과 확정된 변경

목적: 탑차에 상자를 싣는 사용자의 비효율적인 배치·재배치 문제를 해결하여, 유전 알고리즘으로 적재량을 높이고 상차 중 재배치를 줄인다. 웹은 실제 상차 결과와 세대별 변화를 관찰하고 조작하는 수단이다.

사용자는 2026-11-16 「하차가 아니라 상차, 상차를 배워야 한다」고 정정했다. 이어 평가 기준을 「두 기준 함께: 적재량을 높이면서 상차 중 재배치도 줄이기」로 선택했다. 이 요청은 이전 PPT 및 계획의 하차 중심 목적·적합도·재생·완료 기준보다 우선한다. 기존 하차 평가를 실행 화면에서 사용하지 않는다. GA의 진화는 신경망 학습이 아니라 여러 상차 순서·위치 후보를 선택·교차·변이해 개선하는 과정이다.

## 2. 입력과 공통 제약

- 상자 수에는 임의 최대 개수 제한을 두지 않는다. 1 이상의 정수 N과 입력 seed를 받아 극소형~특대형을 각각 20% 확률로 선택한다. 이 비율은 실험 설정이며 실제 택배 분포가 아니다.
- 극소형 80cm/2kg, 소형 100cm/5kg, 중형 120cm/10kg, 대형 140cm/15kg, 특대형 160cm/20kg 이하. cm는 세 변 합이며 모든 등급 최장변은 100cm 이하다. [대한통운 상품규격](https://www.cjlogistics.com/ko/utility/parcel-price), 2026-11-10 확인한 기준이다.
- 각 변은 10~100cm 정수, 중량은 0.1kg 단위, 참고 우선도는 1.0~5.0에서 추첨한다. 치수·무게 판정 등급이 선택 등급과 같을 때만 채택하며 최대 10,000회 재시도한다. 하한·분포는 자체 실험 설정이다.
- 과거 하차용 우선도 속성은 호환성을 위해 보존하되 상차 순서·점수에 사용하지 않는다. 상차 순서는 별도의 순열 유전자다.
- 모든 개체·세대·무작위 비교군은 같은 상자 목록을 공유한다. 입력 seed, GA seed, 도착 순서 seed를 분리한다.
- 가상 적재함 기본 내부 치수는 폭 220·깊이 520·높이 220cm이며 실측 차량 규격으로 단정하지 않는다. 계산 x=폭, y=입구에서 안쪽 깊이, z=높이, 입구는 y=0이다.
- 상자 회전은 고정, 겹침·공간 초과·공중 부양은 금지한다. 밑면 전체를 받치는 지지면 합집합을 검사한다. 면 접촉은 허용한다.
- 이미 확정 상차한 좌표는 변경하거나 임시 이동할 수 없다.

## 3. 개체와 상차 동작

개체는 전체 상자의 목표 좌표 배열과 상차 시도 순서 ID 순열을 함께 가진다. 좌표는 1cm 정수이며 미배치 표시는 (-1,-1,-1)이다. 전부 실을 수 없는 입력에서도 부분 적재 후보를 비교한다. 미적재를 성공한 상차로 표시하지 않는다.

초기 상태는 빈 적재함 또는 이전에 확정된 적재물뿐이다. 순열대로 한 상자씩 입구로 투입한다. 받침 상자가 아직 없으면 해당 상자를 미적재로 남긴다. 평가기가 자동으로 순서를 고쳐서 GA의 순서 오류를 감추지 않는다.

투입 경로의 새 적재물이 방해하면 그 위에 의존하는 상자를 먼저 안전하게 꺼낸 뒤 방해 상자를 임시 이동한다. 신규 상자를 싣고 임시 이동물을 원래 위치에 복귀시킨다. 기존 확정 적재물은 이동하지 않는다. 경로·지지·복귀 실패 시 그 시도의 상태와 이벤트를 되돌리고 해당 상자를 미적재로 남긴다. 재배치 동작을 실제로 확정하지 않은 실패 시도에는 가상의 이동 비용을 부과하지 않는다.

최초 상차는 재배치 0회다. 이미 실은 2kg 상자를 꺼내고 복귀하면 2회·4kg이다. 이벤트는 load(최초 상차), out(임시 꺼냄), return(복귀)을 사용한다. 실제로 수행한 이벤트가 점수와 3D 재생의 동일 근거다.

## 4. 상차 평가식과 기본 가중치

점수 = 100 × 적재율 + 20 × 공간집중도 − 10 × 재배치횟수 − 1 × 재배치중량(kg).

- 적재율 = (실린 개수/입력 개수 + 실린 부피/입력 총부피) / 2. 작은 상자 개수만 늘리거나 큰 상자 부피만 선택하는 한쪽 편향을 줄이기 위해 두 비율을 함께 사용한다.
- 적재함 부피 활용률 = 실린 부피 / 적재함 부피. 화면과 결과 원자료에 별도 표시한다.
- 공간집중도 = 실린 부피 / (적재함 폭 × 높이 × 실린 상자들의 깊이 범위). 같은 양을 실었다면 한 깊이 구역에 더 조밀하게 싣는 배치를 보상한다. 아무것도 실리지 않으면 0이다.
- 100·20·10·1은 변경 가능한 상차용 초기 설정이다. 100·10·1은 이전 PPT 수치의 크기를 이어받았지만, 새로운 적재율 보상과 공간 보상이 있으므로 예전 하차식 및 100점 만점과 동일하지 않다. 공간 보상 20은 상차용 자체 초기값이며 PPT의 수치로 주장하지 않는다.
- 필수 제약을 위반한 배치는 평가·선택에서 제외한다. 단순히 못 실은 상자가 있는 부분 상차는 위반과 구별한다.
- 선형 합산이므로 가중치에 따라 적재량과 재배치 사이의 선택이 달라진다. 모든 입력에서 적재량 최대화가 항상 먼저 이루어지는 사전식 최적화로 주장하지 않는다.

## 5. GA와 실행 제어

집단 50, 총 100세대, 토너먼트 k=3, 좌표 묶음 1점 교차 0.9, 상자별 위치 변이 0.05, 엘리트 1개가 기본이다. 초기 집단이 1세대이므로 100개 집단은 세대 교체 99회다.

순서 유전자는 부모 순열의 접두부와 다른 부모의 미사용 ID를 조합해 중복을 막는다. 순서 변이는 두 위치 교환이다. 좌표 변이는 유효 위치를 찾고 빈 공간이 없으면 두 미고정 좌표를 교환한 뒤 배치를 복구한다. 상자 수용 공간이 모자라면 나머지를 미배치로 남긴다. 부모 ID·연산 종류·수정 여부를 기록한다.

Worker가 짧은 묶음으로 계산하며 완성 세대만 화면에 전달한다. 처음부터 시작은 새 난수 상태와 실행 ID를 사용한다. 일시정지는 부분 세대를 보관하고 재개하며, 정지는 부분 세대를 버리고 마지막 완성 세대 기록을 남긴다. 초기화는 실행·선택·재생 기록을 지우고 입력값은 유지한다.

가중치 적용은 일시정지 후 미완성 세대만 버리고 현재 집단의 상차 원자료를 재채점한다. 과거 세대의 당시 점수는 보존한다. 서로 다른 설정 버전 사이의 점수 차이를 동일 조건의 개선율로 표시하지 않는다.

## 6. 도착·3D·세대 화면

순차 모드는 정해진 무작위 도착 순서를 갖고 대기 공간은 40개다. 꽉 차면 도착을 보류하고 상자를 버리지 않는다. 도착한 상자들로 GA를 실행하고 선택한 결과 중 실제로 실린 상자만 상차 확정한다. 미적재는 대기에 남기고 확정 좌표는 다음 실행에서 고정한다.

오른쪽은 맨 아래 1세대부터 위로 새 세대를 추가한다. 각 후보는 실제 부모 ID로 연결하며 화면에 보이는 세대만 렌더링한다. 과거 또는 현재 개체를 선택하면 해당 목표 좌표·상차 순서로 평가한 결과를 보여준다.

3D는 기존 고정 적재물만 있는 상태에서 시작해 최초 상차·임시 이동·복귀 이벤트를 차례로 보여준다. 개체를 선택하면 최종 실제 상차 상태를 표시하고 상차 재생 버튼으로 처음부터 볼 수 있다. 목표 좌표만 있는 미적재 상자를 실린 것처럼 그리지 않는다. 시도 순서·실제 상차 순서·미적재 ID·적재 개수·부피 활용·공간집중도·재배치 원자료를 확인할 수 있다.

탑차 GLB와 박스 적재 팔레트 C의 재질·소품을 사용한다. 개별 계산 상자는 정확한 규격의 직육면체다. 팔레트 묶음을 택배 한 상자로 간주하지 않는다. 파일 복사본 C/D와 MIT-0 LICENSE는 기존 Asset에 보존한다. 탑차 원본 이용 조건은 외부 배포 전에 확인한다.

## 9. 추가 수정 — 상자 개수·적재함 표시

사용자 지시에 따라 상자 생성의 120개 상한과 입력창 max를 제거했다. 요청 개수만큼 생성하며, 실제로 실릴 개수는 공간·겹침·지지·상차 경로에 따라 결정한다. 기존 순차 도착의 동시 대기 공간 40개는 총 생성·누적 적재 개수 제한과 별도다. 240개 생성 시 ID와 개수·규격·seed 재현을 검증했다.

차체 표시의 기존 5.2m 가정으로 인한 운전석 침범을 수정했다. 원본 에셋의 운전석 후면 x 약 -1.032m, 적재함 외벽 x -0.88~3.55m를 확인하고 내부 x -0.82~3.44m를 공통 기준으로 사용한다. `src/scene/truckFrame.ts`가 모델 배율·바닥·테두리·상자 좌표를 같은 기준으로 변환한다. 폭·높이·깊이를 바꾸어도 운전석과 계산용 적재공간을 분리한다.

## 10. 기본 실행을 총량 제한 없는 자동 공급으로 수정

입력창의 최대값 제거만으로는 기본 18개 목록이 끝나면 실행도 끝나는 문제가 남아 있었다. 사용자가 브라우저에서 18/18개를 지적했으므로 기본 모드를 자동 공급으로 변경했다. 18개는 첫 탐색 입력일 뿐 총량 제한이 아니다. 공급 회차의 탐색 세대가 끝나면 새 상자를 처리 묶음 8개씩 추가하고 다음 회차를 자동 진행한다. 8개 역시 총량·상차 개수 상한이 아니다. 총 공급 회차·총 생성 개수·전체 세대에는 이 자동 공급으로 인한 임의 최대값을 두지 않는다.

최소 생성 치수 10cm 정육면체를 현재 최고 배치에 입구에서 넣을 공간·지지·경로가 있는지 후보 면 좌표를 지연 탐색한다. 위치를 못 찾은 경우 현재 배치의 추가 상차 불가로 알리고 멈춘다. 이는 전역 최적 적재량·모든 재배치까지 고려한 꽉 찬 상태 증명이 아니다. 사용자의 정지·일시정지도 그대로 지원한다. 기본 자동 모드에서는 40개 대기 한도로 전체 공급을 중단하지 않는다. 기존 수동 순차 도착·고정 개수 비교 실험은 별도 선택 모드로 보존한다.

공급 회차가 바뀌면 입력이 달라지므로 새 입력으로 GA 집단을 만들고 이전 최고 실제 배치를 초기 후보 생성의 선호 좌표로 사용한다. 기본 전체 배치 자동 모드는 이전 배치를 재탐색할 수 있으며 수동 순차 도착처럼 강제 고정하지 않는다. 같은 입력 안의 엘리트 보존과 입력이 바뀌는 공급 경계를 구별한다.

전체 세대 번호는 이어지되 ID는 공급 회차별로 구별한다. 각 세대에 당시 상자 목록·고정 좌표를 보존하여 과거 개체의 3D를 최신 입력으로 잘못 재생하지 않는다. 점수 추세와 초기 대비 차이는 동일 공급 회차 안에서 비교한다. 상차 개수 표시에서 /18 같은 유한 입력 분모를 제거하고 현재 선택 배치에 실제 실린 개수만 표시한다. 기본 화면에는 총량 제한 없음·공급 회차를 표시하고 고정 상자 수 입력은 수동 실험 모드에서만 노출한다.
