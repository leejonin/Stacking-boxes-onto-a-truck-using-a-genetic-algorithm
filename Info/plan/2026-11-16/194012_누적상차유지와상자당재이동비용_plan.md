## 구현 계획과 실제 처리

1. 공급 전 선택 개체의 실제 finalCoords와 누적 moves/mass를 LoadingSnapshot으로 확정한다. 전체 입력을 실은 후보가 있으면 그 후보 중 최고 점수를 선택하고, 없으면 현재 최고 점수 배치를 선택한다. 모든 후손은 확정한 상자 ID를 유지해야 한다. 기존 상자를 미적재로 만드는 후보는 제외한다.
2. simulateAccumulatedLoading은 이전 적재 상태에서 시작한다. 목표 좌표가 변경된 기존 상자, 상차 경로·지지 때문에 임시 이동한 상자를 꺼내고 실제 가능한 지지·경로 순서로 복귀한다. 복귀하지 못한 기존 상자가 있으면 무효다. 한 회차의 후보 실행에서 재이동한 상자 ID 집합을 사용해 꺼냄·복귀를 합쳐 1회·해당 중량을 계산한다. 최초 상차는 무료다. 이전 공급의 누적 비용에 더한다. 같은 상자가 다음 공급에서 다시 이동하면 다시 1회다.
3. 고정 좌표 제약과 구별한다. 자동 공급의 기존 상자는 이동 가능하나 유실 불가이며, 수동 순차 도착의 고정 적재는 기존대로 이동 불가다. 수동 고정 입력 비교 실험의 기존 꺼냄·복귀 각각 비용 방식은 보존한다.
4. Engine의 공급 계승 때 확정 적재물을 유지할 수 있는 부모만 재평가·계승한다. 무효 후손을 반복 생성하는 대신 검증된 부모를 복제하여 진행한다. 가중치 100/10/1/공간20과 최초 입력 보상 기준은 유지한다. 과거 공급 비용을 초기화하지 않는다.
5. 세대마다 당시 누적 시작 상태를 보존한다. App 재생은 동일 누적 평가기를 사용하고 3D 시작 좌표에는 기존 적재 상태를 전달한다. 기존 상자를 빈 적재함에서 다시 싣는 것으로 표시하지 않는다.

## 2026-11-16 19:42:17 (KST) 사용자 추가 조건 — 짐칸이 꽉 찼을 때만 완료
